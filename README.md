# Контрольная работа №2 — вариант 1

Проект: [`Control_Work_02_Polymorphism`](Control_Work_02_Polymorphism), C++17 / Qt 5 или Qt 6.
Выполнены задания 1, 2, 3 **только варианта 1** и обязательная для всех вариантов
интеграция `Autopilot` из PDF. Другие варианты заданий не реализованы.

## Состав решения

| Задание | Реализация |
| --- | --- |
| 1 | Абстрактный `UAV`, `Quadcopter`, `FixedWingUAV`, универсальная `run_flight_test(UAV&)` |
| 2 | Абстрактный `Sensor`, `Gyroscope` (1.25 rad/s), `Accelerometer` (9.81 m/s²), `Barometer` (1012.8 hPa), `std::vector<Sensor*>`, `check_sensors`, сеттеры готовности |
| 3 | `Position`, абстрактный `NavigationSystem`, `GPSNavigation` (`satellites >= 4 && valid`), `VisualNavigation` (`target_tracked`), `print_navigation_status` |
| Интеграция | `Autopilot::run_cycle()`, цель 200 м, шаг 0.1 с, абстрактный `FlightController` и минимальный `SimpleController` с коэффициентом 0.5 |

`SimpleController` необходим для обязательной интеграции: при высоте 150 м ошибка
равна 50 м, управление — 25. PID/Fuzzy и остальные задания других вариантов не добавлены.
Абстрактные базы имеют виртуальные деструкторы, переопределения помечены `override`,
состояние инкапсулировано. Универсальные функции используют только интерфейсы,
без проверки конкретного типа. Вывод модели — через `qDebug()`.

Сенсоры в примере возвращают заданные константы, а не физически рассчитанные
показания. Неготовый сенсор не опрашивается при проверке; прямой вызов `read()`
у него возвращает NaN с диагностикой. Пустой набор, нулевой указатель и
неконечное показание приводят к `sensor failure`.

`is_valid()` навигации следует формулам задания. Координаты дополнительно
проверяются отдельно: конечные значения, широта ±90°, долгота ±180°,
неотрицательная высота. Некорректную позицию можно сохранить для демонстрации
ошибки, но автопилот её отклоняет. `Autopilot` не владеет указателями модулей;
все модули должны существовать до завершения его работы.

## Сборка и запуск

Откройте `CMakeLists.txt` рядом с этим README либо
`Control_Work_02_Polymorphism/CMakeLists.txt` в Qt Creator.
Нужны модули одной версии Qt: Core, Widgets, 3DCore, 3DRender, 3DExtras,
3DInput, Multimedia, Svg; для проверок окна — Test.

Из каталога с этим README (`Kr2` в исходной коллекции работ или корень
отдельного репозитория `UAV_KR2`):

```sh
cmake -S Control_Work_02_Polymorphism -B build
cmake --build build -j2
./build/Control_Work_02_Polymorphism
QT_FORCE_STDERR_LOGGING=1 ./build/polymorphism_demo
ctest --test-dir build --output-on-failure
```

Консольный вариант без графических модулей:

```sh
cmake -S Control_Work_02_Polymorphism -B build-console -DKR2_BUILD_GUI=OFF
cmake --build build-console -j2
ctest --test-dir build-console --output-on-failure
```

## Визуализация

Использованы те же методы, что в предыдущих работах:

- **Qt3D:** перенесены `scene3d`, `dronevisual`, `point3d` из `Practical_02_Task_2`.
  Площадка 600 × 400 м, сетка 50 м, цветные оси, маршрут, маркер аппарата,
  линия высоты, изображение, приближение/отдаление, фокус на БПЛА и общий вид.
- **QPainter:** `SignalGraph` адаптирован из `BatteryGraph`: графики высоты,
  управления и трёх сенсоров с отдельными единицами измерения. Пунктир — 200 м.
  Хранятся последние 600 измерений. При отказе сенсора новые точки не добавляются.
- **Qt Multimedia:** подход из `Practical_03_Classes/ew_route_3d/flightaudio`:
  зацикленный звук полёта и предупреждение об ошибке. Звук выключается флажком.
- **Изображения:** существующая фотография `drone.jpg` и SVG-схема самолёта;
  встроены вместе со звуками в ресурсы `.qrc`, внешние пути не нужны.

На вкладке **«1. БПЛА»** выберите аппарат и запустите испытание. Консольная функция
выполняется сразу; окно за 12 секунд воспроизводит его учебную траекторию.
Квадрокоптер взлетает и садится вертикально, самолёт сначала разбегается,
затем набирает высоту и садится с планированием. Это демонстрация типов взлёта
и посадки, не аэродинамический расчёт.

На вкладке **«2. Сенсоры»** показаны значения и готовность. Снятый флажок имитирует
отказ. **«Проверить сенсоры»** выполняет полиморфный обход.

На вкладке **«3. Навигация»** выберите GPS или визуальную навигацию, измените
спутники/валидность GPS, отслеживание визуальной цели или позицию. Кнопка проверки
выводит статус и показывает допустимую высоту в 3D. Обе системы получают
одинаковую введённую позицию. Автоматического переключения между ними нет — оно
относится к другому варианту. Широта/долгота не преобразуются в координаты сцены:
3D показывает локальную учебную траекторию и высоту.

На вкладке **«Интеграция»** кнопка **«Выполнить один цикл»** проверяет модули и
вычисляет управление без перемещения. **«Анимация до 200 м»** дополнительно
применяет учебную модель `h += control * 0.1` каждые 0.1 с. Завершение — при
ошибке не более 0.1 м. В этой демонстрации показывается только регулирование
высоты, без аэродинамики самолёта. Во время движения можно вызвать отказ сенсора,
GPS/визуальной навигации или отключить контроллер: следующий цикл остановит
анимацию, выведет причину и включит предупреждение.

**«Остановить анимацию»** сохраняет текущий результат, **«Сбросить»** возвращает
штатный сценарий (150 м, GPS, восемь спутников, все сенсоры готовы).
Начало анимации или сброс очищают графики. Журнал хранит последние 600 строк.

## Проверки

`polymorphism_demo` показывает все три задания и пять обязательных сценариев:

1. Штатный цикл: высота 150 м, ошибка 50 м, управление 25.
2. Неготовый сенсор: `Autopilot cycle aborted`, `Reason: sensor failure`.
3. Невалидная навигация: `Navigation data invalid`.
4. Нулевой контроллер: `Error: flight controller is not set`.
5. Отрицательная высота: `Error: invalid navigation position`.

`polymorphism_tests` проверяет эти сценарии, точный контрольный вывод,
границу 3/4 спутника, потерю цели, заменяемость модулей, NaN/Infinity,
нулевые указатели и отсутствие чтения неготового сенсора.
`polymorphism_window_tests` проверяет действия окна, отказы при движении,
сходимость высоты, анимации обоих БПЛА, встроенные изображения/звуки и графики.
CTest запускает окно с `QT_QPA_PLATFORM=offscreen`, без проверки настоящего рендера
или аудиоустройства. Дополнительная проверка 3D на рабочем столе с сохранением PNG:

```sh
KR2_SCREENSHOT=/tmp/kr2 ./build/polymorphism_window_tests
```
